## Схема архитектуры

```text
               ┌──────────────────────┐
               │   Исходный код (.wh) │
               └──────────┬───────────┘
                          │
                          ▼
               ┌──────────────────────┐
               │    Лексер и парсер   │ ◄─── whalli-lsp (Language Server)
               └──────────┬───────────┘
                          │ AST
                          ▼
               ┌──────────────────────┐
               │  Компилятор байткода │
               └──────────┬───────────┘
                          │ Чанки инструкций
                          ▼
         ┌───────────────────────────────────┐
         │     Стековая виртуальная машина   │
         │ ┌───────────────┐ ┌─────────────┐ │
         │ │  Планировщик  │ │ Поллер MIO  │ │
         │ │    ворутин    │ │ (EventLoop) │ │
         │ └───────────────┘ └─────────────┘ │
         │ ┌───────────────┐ ┌─────────────┐ │
         │ │  Куча и GC    │ │     API     │ │
         │ │ (Mark&Sweep)  │ │   модулей   │ │
         │ └───────────────┘ └─────────────┘ │
         └───────────────────────────────────┘
```

## Конвейер компилятора

1. **Лексер (`src/lexer.rs`)**: Разбивает исходный текст на токены, обрабатывает строковую интерполяцию (`f"..."`), комментарии и литералы.
2. **Парсер (`src/parser.rs`)**: Рекурсивный нисходящий парсер, строящий типизированное дерево абстрактного синтаксиса (`src/ast.rs`).
3. **Компилятор (`src/compiler.rs`)**: Генерирует линейный байткод инструкций стек-машины, разрешает локальные переменные, замыкания и переходы циклов.
4. **Виртуальная машина (`src/vm.rs`)**: Выполняет байткод в многопоточном пуле с алгоритмом work-stealing, переключает контекст ворутин и опрашивает сетевые события через `mio`.

## Управление памятью и GC

Объекты кучи Whalli размещаются в чанковом пуле слотов памяти:
- **Сборщик мусора Mark-and-Sweep**: Периодически трассирует живые ссылки из стеков всех активных ворутин, глобальных переменных и очередей сообщений.
- **Адаптивный порог**: Порог срабатывания GC динамически подстраивается под нагрузку (`max(живых_объектов * 2, 256)`).
- **Потокобезопасность**: Доступ к слотам кучи защищен легкими блокировками `parking_lot::RwLock`.
